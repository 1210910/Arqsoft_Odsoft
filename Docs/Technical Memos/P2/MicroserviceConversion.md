# Technical Memo: Conversion to Microservices


| **Element**        | **Statement**                                                                                                                                                                                                                                                             |
|---------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Stimulus**        | The monolithic architecture limits scalability and maintainability, making it necessary to separate concerns into distinct collaborating applications to support distributed development and deployment.                                                                |
| **Stimulus Source** | The need to transition from a monolithic architecture to a distributed system aligned with business domains, enabling better scalability, fault isolation, and team autonomy.                                                                                            |
| **Environment**     | The application operates in a microservices architecture, utilizing patterns like CQRS, database-per-service, and messaging, with RabbitMQ as the AMQP broker for inter-service communication.                                                                           |
| **Artifact**        | The LMS Software, originally a monolithic application, now redesigned into microservices.                                                                                                                                                                              |
| **Response**        | Segregate the monolith into the following microservices: **Books**, **Readers**, and **Lendings**, each responsible for a distinct domain. Additional microservices were created for **Top 5 Queries** (optimized heavy-query handling) and **Auth & Users** (authentication and user management). |
| **Response Measure** | Each microservice should operate independently, communicate via RabbitMQ, and maintain its own database (database-per-service). Scalability and fault tolerance should be validated through the deployment of multiple instances in containers or virtual machines.                                           |
